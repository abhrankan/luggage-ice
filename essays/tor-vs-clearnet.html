Tor vs clearnet: what changes, what doesn't

Running a site on Tor instead of the clearnet changes some things substantially and leaves others exactly the same. The distinction matters because it is easy to overestimate what Tor provides and equally easy to underestimate what remains your responsibility.

What Tor actually does

Tor hides the network location of both the server and the visitor. A clearnet server has an IP address that can be traced to a hosting provider, a jurisdiction, and often a person or organization. A Tor hidden service has an onion address derived from a cryptographic key pair. The address reveals nothing about where the server is physically located or who controls it.

For visitors, Tor anonymizes their origin. Their ISP sees that they are using Tor but cannot see which sites they visit. The site they visit sees a Tor exit node or, in the case of a hidden service, no exit node at all — the connection stays entirely within the Tor network.

What Tor does not do

Tor does not protect against mistakes made at the application layer. A hidden service that logs user-agents, serves personalized content, or loads external resources can still correlate visitors through those mechanisms. Tor provides network anonymity. It does not compensate for a site that actively undermines it.

Tor does not protect the content of the site itself. If the files served contain identifying information — an author's writing style, specific details known only to a small group, metadata embedded in images — that information is still present regardless of the transport layer.

Tor does not guarantee uptime or discoverability. Onion addresses are not indexed by search engines. There is no DNS propagation to manage, but there is also no infrastructure to help people find a service they do not already know the address of. Distribution of the address is entirely the operator's responsibility.

What stays the same

The web stack. HTML, CSS, HTTP — these work identically over Tor. A static site built for the clearnet can be served as a hidden service with no modifications to the files themselves. The server configuration changes; the content does not.

Security hygiene at the application level. Keeping software updated, using strong keys, not logging unnecessary data — these remain as important on Tor as anywhere else, arguably more so, because the operator has chosen to reduce their exposure to legal and administrative remediation in the event of a compromise.

The honest summary

Tor shifts where anonymity is enforced from the application to the network layer. That is a significant shift. But it is not a complete solution. A site on Tor that is carelessly built can still leak information about its operator and its visitors. Tor is a strong tool used in combination with careful design — not a substitute for it.
