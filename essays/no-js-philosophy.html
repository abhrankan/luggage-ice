Philosophy

Why this site has no JavaScript

The default assumption in web development today is that JavaScript is present, available, and necessary. This site rejects that assumption. Not as a technical constraint, but as a deliberate position.

JavaScript is not neutral

Every script that runs in a browser is code executing on someone else's machine without their full knowledge of what it does. On the clearnet this is normalized. On Tor, where people arrive specifically because they want less of that, it is a contradiction. A hidden service that loads JavaScript is asking its visitors to trust code they cannot easily inspect, running in an environment they are trying to protect.

The Tor Browser ships with JavaScript enabled by default for usability, but its highest security setting disables it entirely. A site that requires JavaScript excludes the most security-conscious visitors on the network — the ones with the most reason to be there.

What JavaScript is usually solving

Most JavaScript on informational sites solves problems that were introduced by other JavaScript. Frameworks that need hydration. Lazy loaders that compensate for oversized bundles. Analytics that justify their own existence. Strip those layers away and the underlying content rarely needed any of it.

Interactive accordions, responsive layouts, smooth navigation — all of these can be handled with <details>, CSS grid, and anchor links. The browser already knows how to do these things. JavaScript is often what gets in the way of letting it.

The trust argument

Removing JavaScript is also a statement about trust. A page with no scripts makes an implicit promise: what you see is what was written. There is no runtime deciding what to show you, no A/B test serving a different version, no fingerprinting script building a profile from your interaction patterns.

That promise is difficult to fake. You can verify it by viewing the source. On a network built around anonymity, verifiability is a form of respect.

What is lost

Interactivity that genuinely requires computation. Real-time updates. Complex UI state. These are real trade-offs, and for sites that need them, they are valid reasons to use JavaScript. This site does not need them. The decision to omit JavaScript here is not a universal prescription — it is an honest match between the tool and the task.
